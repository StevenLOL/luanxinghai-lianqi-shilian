# 003 竞品分析（规则6）

> 目标：为「fighter fragment 的下载 / 端侧运行 / Godot 移植」调研寻找竞品与可复用方案。
> 落盘目录：`others/`。clone 方式：`git clone --depth 1`（规则6.1）。

## 竞品 1：twopoint5d（已 clone 分析）

- 仓库：https://gitee.com/atuxe/twopoint5d （上游 spearwolf/twopoint5d）
- License：Apache-2.0（宽松，可商用）
- 技术栈：three.js + TypeScript，monorepo（Nx/pnpm）
- 形态：`@spearwolf/twopoint5d`（vanilla JS）与 `twopoint5d-r3f`（React Three Fiber）
- 能力：2.5D sprite/particle、图集、sprite-sheet 动画、billboard、2.5D 地图、TexturePacker/tiled/LDtk 导入（部分规划中）
- 本地：`others/twopoint5d/`（76MB；Windows 下 checkout 有路径告警，README/package.json 可读）
- **对本调研的意义**：证明 sprite-stacking/2.5D 生态主流走 three.js；而目标 fragment 是自研 Canvas-2D 软件渲染器（零 three.js 依赖）。两者路线不同——目标游戏**更容易脱离引擎独立运行**（只需 Canvas + 少量 WebGL），但**更难直接映射到 Godot 的 3D 管线**。

## 竞品 2：Godot SpriteMesh 插件（社区方案，未 clone，存档信源）

- 信源：https://blog.csdn.net/weixin_42526249/article/details/160724775
- 机制：按 alpha 阈值把 2D 精灵“挤出”为带厚度的 3D Mesh，支持逐帧动画网格、双面渲染、像素尺寸参数
- **意义**：若在 Godot 复刻 sprite-stack 观感，这是最贴近的现成工具，但只解决“几何/观感”，飞行/战斗/镜头逻辑仍需自写。

## 竞品 3：VoxCSS / SpriteJS（生态参考，未 clone）

- VoxCSS：https://github.com/LayoutitStudio/voxcss —— DOM+CSS 体素引擎，无 WebGL
- SpriteJS：https://gitee.com/hljcc/spriteJS —— 360 开源跨端 Canvas/WebGL2 图形系统
- **意义**：再次印证“体素/sprite-stack 渲染可在纯 Web 标准 API 上实现”，与 fragment 的技术选择一致。

## 结论

- Web 侧：已有成熟 2.5D 生态（three.js 系 + Canvas 系），目标 fragment 属后者且高度自包含。
- Godot 侧：缺少“一键导入 Web fragment”的现成桥；可行路径是 WebView 封装或源码级移植，SpriteMesh 类插件可辅助观感复刻。
- 竞品不足以提供“直接把该 fragment 变成 Godot 工程”的捷径，印证报告 §4 的判定。
