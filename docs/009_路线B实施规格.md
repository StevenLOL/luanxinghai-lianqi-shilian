# 009 路线 B 实施规格：真 3D 舞台 + 3D 空间切片体单位

> 决策来源：`docs/008` §5.6 / ADR-2（用户 2026-11-17 14:02 确认）。
> 目标：在 Godot 4.7.2 里既拿到真 3D 的相机/空间/光照/导航，又不要求先产出成套 3D 骨骼美术资产。
> 本文件是**可执行规格**，不是方向描述。

---

## 0. 一句话定义

**舞台是真的 3D；单位是 3D 空间里一组朝向相机的切片面片，靠 Y 向错位叠出体积。**  
相机可以真转，切片始终面对相机，所以不露纸片侧面；等有 3D 美术了，只换单位表现层，逻辑层不动。

---

## 1. 渲染分层总览

| 层 | 技术 | 节点 | 说明 |
|---|---|---|---|
| L1 天空/云海 | WorldEnvironment + 远云 impostor | `WorldEnvironment`、`Clouds` | 云海用 billboard/impostor，不建模 |
| L2 地形 | 高度场 Mesh + 水面 Shader | `Terrain`、`Water` | 山/海/洞天，真 3D，参与遮挡与寻路 |
| L3 单位 | 切片体 MultiMesh | `Units` | 玩家/队友/妖兽/敌修/神兽 |
| L4 法术特效 | GPUParticles3D + ShaderMaterial | `FX` | 剑光、雷池、尾焰、护体罡气 |
| L5 地面提示 | Decal / 半透明圆面 | `FX/GroundIndicators` | 法术范围圈、阴影、选中框 |
| L6 UI | CanvasLayer | `UI` | HUD、宗门面板，与 3D 解耦 |

### 推荐节点树

```text
Main (Node3D)
├─ World (Node3D)
│  ├─ Terrain (StaticBody3D + MeshInstance3D)
│  ├─ Water (MeshInstance3D)
│  ├─ Clouds (Node3D)                 # impostor
│  ├─ NavigationRegion3D
│  └─ DirectionalLight3D
├─ Units (Node3D)
│  ├─ SliceStacks (Node3D)            # 每原型一个 MultiMeshInstance3D
│  └─ Logic (Node3D)                  # CharacterBody3D + NavigationAgent3D
├─ FX (Node3D)
│  ├─ Spells (Node3D)
│  └─ GroundIndicators (Node3D)
├─ CameraRig (Node3D)                  # yaw
│  └─ PitchArm (Node3D)               # pitch
│     └─ Camera3D
└─ UI (CanvasLayer)
```

**关键原则：表现层（`SliceStacks`）与逻辑层（`Logic`）分离。** 逻辑层只持有 `position`、`altitude_layer`、`facing`，不知道自己是被切片还是网格画出来的。这是将来换真 3D 模型的接口基础。

## 2. 切片体单位渲染

### 2.1 数据：从 fighter 体素到切片图集

fighter 的模型是代码内 RLE + base64 体素（`scene.ts`）。转换管线：

```text
体素数据 (RLE/base64)
  → 按 Y 层切片（每 N 体素一层，N=2~4）
  → 每层正交俯视渲染成透明 PNG（切片轮廓）
  → 所有层 + 所有角度打包进 atlas（如 8×8 格）
  → 生成 SliceSetDef 资源，记录每层的 UV 矩形与 Y 偏移
```

脚本文案：`scripts/07_voxel_to_slices.py`（按规则放 `scripts/`，详细注释）。  
产出资源：`data/units/<id>_slices.tres`。

### 2.2 Mesh：每个原型烘焙一个含全部切片的 ArrayMesh

不要每层一个 MeshInstance3D——30 单位 × 12 层 = 360 个节点，太碎。做法：

- 一个单位原型 = 一个 `ArrayMesh`，包含 N 个 quad，每个 quad 的 UV 指向 atlas 中对应切片；
- quad 的局部 Y = `layer_index * spread`，`spread` 沿用 docs/006 的经验值（**小值**，过大就散架）；
- 这个 ArrayMesh 作为 `MultiMesh.mesh`，同类单位一次实例化画完。

### 2.3 材质：billboard + alpha scissor

```gdscript
var mat := BaseMaterial3D.new()
mat.billboard_mode = BaseMaterial3D.BILLBOARD_ENABLED  # 整组切片朝向相机
mat.transparency = BaseMaterial3D.TRANSPARENCY_ALPHA_SCISSOR  # 关键
mat.alpha_scissor_threshold = 0.5
mat.texture_filter = BaseMaterial3D.TEXTURE_FILTER_NEAREST   # 保国风锐利边缘
mat.vertex_color_use_as_albedo = true                        # 受击闪红 / 阵营染色
```

**为什么必须是 `ALPHA_SCISSOR` 而不是 `ALPHA_BLEND`：** Godot 官方性能文档（S25）明确说明，自动实例化只对不透明或 alpha test 材质生效，alpha blend 材质不会被实例化。切片是硬边轮廓，正适合 scissor；顺带避免半透明排序错误。

### 2.4 实例化

```gdscript
@onready var multimesh: MultiMeshInstance3D = $SliceStacks/WolfStack

func setup_units(def: UnitDef, units: Array[UnitLogic]) -> void:
    var mm := MultiMesh.new()
    mm.transform_format = MultiMesh.TRANSFORM_3D
    mm.mesh = def.slice_mesh                 # 含全部切片的 ArrayMesh
    mm.instance_count = units.size()
    for i in units.size():
        mm.set_instance_transform(i, units[i].logic_transform)
        mm.set_instance_color(i, units[i].tint)   # 受击/阵营
    multimesh.multimesh = mm
```

每个单位原型一个 `MultiMeshInstance3D`；同屏 6 个原型 ≈ 6 个 draw call。

### 2.5 相机限位（防露馅的核心）

切片始终面向相机，所以 yaw 可以放开；但 pitch 太大时会看到层间缝隙。限制：

- **yaw**：基准 ±60°（覆盖 G5"多角度"，又不出国风构图）；
- **pitch**：三档预设 25° / 45° / 70°，滚轮或双指切换；超过 70° 直接拒绝；
- 平滑过渡 0.15~0.25s，不要瞬切。

节点树与控制：

```text
CameraRig (Node3D)        # rotation.y = yaw
└─ PitchArm (Node3D)      # rotation.x = -pitch
   └─ Camera3D            # position.z = distance
```

```gdscript
extends Node3D
@export var pitch_presets: Array[float] = [25.0, 45.0, 70.0]
@export var yaw_limit: float = 60.0
var _yaw: float = 0.0
var _pitch_idx: int = 1

func _unhandled_input(e: InputEvent) -> void:
    if e is InputEventMouseMotion and (e.button_mask & MOUSE_BUTTON_RIGHT) != 0:
        _yaw = clampf(_yaw - e.relative.x * 0.12, -yaw_limit, yaw_limit)
    if e is InputEventMouseButton and e.pressed:
        if e.button_index == MOUSE_BUTTON_WHEEL_UP:
            _pitch_idx = mini(_pitch_idx + 1, pitch_presets.size() - 1)
        elif e.button_index == MOUSE_BUTTON_WHEEL_DOWN:
            _pitch_idx = maxi(_pitch_idx - 1, 0)
```

移动端：空白处单指拖动 = yaw；双指上下 = pitch 档位；与 fighter 的 `pointer:coarse` 输入映射保持一致。

### 2.6 与真 3D 舞台的交互

| 需求 | 做法 |
|---|---|
| 单位贴地 | 逻辑层用 `RayCast3D` 打 `Terrain` 取高度；切片体本身不参与物理 |
| 寻路 | `NavigationAgent3D` 挂在逻辑层；飞行单位开 `use_3d_avoidance`（S23/S24） |
| 阴影 | 不用切片真实投影；地面放一个半透明圆面 blob shadow（省性能且风格统一） |
| 遮挡 | 切片体是真 3D 空间对象，自动参与深度测试；山体挡住单位自然成立 |
| 法术范围 | 地面投影圈（半透明圆面/Decal），解决 docs/006 提过的"范围看不清" |
| 高度层 | `altitude_layer` 决定逻辑 Y 偏移；雷池打 GROUND，剑气可打 LOW_AIR |

## 3. 资产转换管线验收

`07_voxel_to_slices.py` 必须满足：

1. 输入 fighter 体素数据，输出每层 PNG + atlas + `.tres`；
2. 层数可配（默认 10~14），`spread` 可配；
3. 输出 atlas 必须是硬边 alpha，不允许半透明羽化（否则 scissor 会锯齿）；
4. 生成 `.tres` 含：`slice_mesh`、`atlas`、`layer_count`、`spread`、`bounds`；
5. 脚本带详细中文注释（规则2）。

验证：随机抽 3 个体素模型，转出来的切片体在 Godot 里 45° 截图，与 fighter 原截图并排比对体积感。

## 4. 性能预算

| 项 | 估算 | 说明 |
|---|---|---|
| 单位切片 | 30 单位 × 12 层 × 2 三角 ≈ 720 三角 | 可忽略 |
| 单位 draw call | 原型数（约 6） | MultiMesh 合批 |
| 地形 | 高度场 1~2 draw call | 静态 |
| 法术 | GPUParticles3D 数个 | 移动端降粒子数 |
| 云海/远景 | impostor 数个 | S25 推荐 |
| **目标** | 移动端 60fps、PC 120fps | 低端机优先降 `pixelSize` 与粒子数，不降单位逻辑 |

**移动端基线沿用 docs/006**：`pixelSize:2`、`grain:0`、`bloom:0.4`。切片体用 nearest 过滤保锐利，别再叠 grain。

## 5. 升级到真 3D 网格的接口

`UnitDef` 预留表现策略字段：

```gdscript
class_name UnitDef extends Resource
@export var id: StringName
@export var representation: Representation = Representation.SLICE_STACK
@export var slice_set: SliceSetDef
@export var mesh_3d: PackedScene              # 将来填
@export var logic_scene: PackedScene          # 不变

enum Representation { SLICE_STACK, MESH_3D }
```

表现层工厂：

```gdscript
func create_visual(def: UnitDef) -> Node3D:
    match def.representation:
        Representation.SLICE_STACK:
            return SliceStackVisual.new(def.slice_set)
        Representation.MESH_3D:
            return def.mesh_3d.instantiate()
```

战斗逻辑、寻路、数据、存档完全不依赖 `representation`。将来有 3D 美术时，只改 `.tres` 的字段，不动一行战斗代码。

## 6. 实施顺序与验收门槛

| 步骤 | 交付 | 通过标准 |
|---|---|---|
| S1 | Godot 空场景 + 高度场地形 + CameraRig | yaw ±60 / pitch 三档可用，地形遮挡正确 |
| S2 | 1 个单位原型切片体（体素转换 → atlas → MultiMesh） | 45° 下体积感接近 fighter |
| S3 | 30 单位压力场景 | 帧率达标；相机转动不露馅；alpha scissor 无排序错误 |
| S4 | 法术地面投影圈 + 飞行高度层 | 范围可读；低空/高空避让生效 |
| S5 | 4 原型 + 1 神兽 Boss | 满足 P2 战斗切片要求 |

**决策门（S3 后评审）：**
- 若 70° 俯角仍明显看到层间缝隙 → 把 pitch 上限压到 55°，或减小 `spread`；
- 若切片体在真 3D 光照下观感崩坏 → 给切片材质关闭受光（`unshaded`）或改为自发光，保留国风平涂；
- 若以上都救不回来 → 触发 `docs/008` §5.6.5 的转路线 A 条件评审，不要硬撑。

## 7. 风险登记

| 风险 | 触发 | 对策 |
|---|---|---|
| 切片在 3D 光照下发灰/脏 | 真 3D 灯光打到平涂切片 | 材质设 `unshaded` 或专用 shader，不接 PBR 光照 |
| 高 pitch 露层 | 70° 俯视 | 压 pitch 上限；减小 spread；层间加半透明过渡边 |
| alpha scissor 锯齿 | atlas 边缘有羽化 | 转换管线强制硬边 alpha |
| 资产转换耗时 | 体素模型多 | 脚本批处理 + 缓存 `.tres`，只转变更的模型 |
| 与 P0 Web 原型观感不一致 | 两端参数没对齐 | 只共享参数与数据，不要求像素级一致；以 Godot 版为准 |

**先用切片体把玩法跑通，同时把 `UnitDef.representation` 留好；有 3D 美术后改一个枚举值就能升级，前面的战斗逻辑一行不用重写。**
