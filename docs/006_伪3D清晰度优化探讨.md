# 006 探讨：如何提升 fighter 伪 3D 视角的清晰度

> 规则 3/5/7：调研输出落盘、信源保留。时间 2026-11-17 12:10–12:40 GMT+8。
> 方法：源码级分析 + 本地参数对比实测（4 组真实截图）。

---

## 0. 核心结论（先看）

这个游戏的"清晰度"**不是一个旋钮，而是四个不同层面**。按收益/成本排序：

| 优先级 | 手段 | 参数 | 效果 | 成本 |
|--------|------|------|------|------|
| 🥇 1 | **降低 pixelSize** | `pixelSize: 3 → 1` | **决定性**。缓冲分辨率从 ~427×267 升到 1280×800，细节提升最显著 | 中～高（软件渲染像素量 ×9，掉帧风险，低端机慎用） |
| 🥈 2 | **关掉"软"后处理** | `bloom/grain/vignette: → 0` | 去掉发光光晕、噪点、暗角，边缘更干净、颜色更实 | 几乎为零（渲染更快） |
| 🥉 3 | **放大机体/换视角** | `jetScale↑`、`view:'top'` | 让机体占更多屏幕像素，伪3D 层更可辨 | 低（改变构图） |
| 4 | **`spread` 切片间距** | 保持在 1～2 | ⚠️ **不是清晰度旋钮**。实测 spread=4 机身直接散成碎片 | — |

**推荐组合**（桌面高性能设备）：`pixelSize: 1, bloom: 0.3~0.5, grain: 0, vignette: 0.1~0.2, jetScale: 0.8`。
**移动端/Android**（结合 004 的性能风险）：`pixelSize: 2, grain: 0, bloom: 0.4`，先保 60fps。

## 1. 渲染管线：清晰度在哪里决定（源码实证）

一帧的生成（`fighter-jet-eject.tsx:389-402` + `scene.ts:4577` + `post.ts`）：

```
scene.render()              体素切片 → 写进低分辨率 Uint8ClampedArray 帧缓冲
   ↓
post.apply(fb, W, H, look)  bloom 辉光 / vivid 对比 / vignette 暗角 / grain 噪点
   ↓
ctx.putImageData(image)     把缓冲画到 canvas（canvas.width=lw, height=lh）
   ↓
CSS 放大 px 倍              canvas.style.width = lw*px；image-rendering:'pixelated'
   ↓
+ WebGL 火焰层              独立 canvas，全分辨率（DPR≤2）
```

关键代码（一手，本地已落盘）：

- `fighter-jet-eject.tsx:240-247`：
  ```js
  const auto = Math.min(12, Math.max(2, Math.round(Math.sqrt((cw * ch) / 100000))))
  const px = pixelRef.current > 0 ? Math.round(pixelRef.current) : auto
  const lw = Math.ceil(cw / px)
  const lh = Math.ceil(ch / px)
  ```
  → **`px = pixelSize` 直接决定缓冲宽高**。1280px 宽时：px=3 → 427px 缓冲；px=1 → 1280px 缓冲。
- `fighter-jet-eject.tsx:697`：`style: { imageRendering: 'pixelated' }` —— **硬像素放大已启用**，没有双线性模糊。所以"糊"不是插值造成的，而是缓冲分辨率本身低。
- `scene.ts:1249 resize(w,h)`：`fb = new Uint32Array(w*h)` 按缓冲大小分配，像素量随 `px²` 变化。
- `scene.ts:4672-4677`：`post.apply(fb, W, H, look)` 中 `look.bloom/vivid/vignette/grain` 直接来自参数。

**结论**：想清楚 → 提高缓冲分辨率（降 pixelSize）；想干净 → 降后处理；这两个是独立的。

（注：截图中出现纯色天空帧是因为游戏自动演示时相机会指向天空；脚本用文件大小 >60KB 判定有效帧并重试，已记录在脚本注释。）

### 2.1 性能代价（必须一起看）

- `pixelSize=1` 时缓冲像素量 = `(1280×800) / (427×267) ≈ 9 倍`。scene.ts 是**纯 JS 逐像素软件光栅化 + 每帧一遍 bloom 模糊**（`post.ts` 的 blur 在半分辨率图上做），CPU 开销近似线性增长。
- 截图本身成功（说明桌面端能渲染），但**移动端/Android 上极可能掉帧**——这正是 004 文档标记的头号风险。
- 因此移动端建议 `pixelSize:2`（约 2.25 倍像素量，折中），而不是 1。

## 3. 每个旋钮的正确用法

### 3.1 pixelSize（首要）
- `0` = 自动：`clamp(round(sqrt(面积/100000)), 2, 12)`，随窗口大小自适应；1280×800 时约 3。
- `1` = 最清晰，代价最高；`2` = 折中；`≥3` = 复古像素风、省性能。
- 它同时影响 `image-rendering:pixelated` 的块大小 —— 降它=缩小块=更清晰。

### 3.2 bloom / grain / vignette（免费提升"干净度"）
- `bloom`（辉光）：0.8 默认偏高，会让火光/阳光周围的像素"化开"。降到 0.3~0.5 保留氛围又不太糊。
- `grain`（胶片颗粒）：0.25 默认会叠加噪点，直接降低有效清晰度 → 建议 0 或 0.05。
- `vignette`（暗角）：0.3 默认让四角变暗，边缘细节丢失 → 0.1~0.2 或 0。
- `vivid`：颜色深度/对比，适度提高（0.3~0.5）会让轮廓更分明。

### 3.3 spread（切片间距）—— 小心
- 定义：体素切片绘制时横向错开的像素距离，制造伪 3D 的厚度感。
- 实测：1 → 机身紧凑；4 → **散架**。建议保持 1，最多 2。想增强 3D 感应靠视角/机体大小，不要靠拉大 spread。

### 3.4 view / jetScale / 其他
- `view:'top'`：俯视最能看清 sprite-stack 的分层结构；`'chase'`（默认）机身小；`'cockpit'` 有座舱遮挡但沉浸。
- `jetScale`：0.6 → 0.8~1.0 让机体占屏更多，细节自然更可见。
- `chaseSize`（追尾时机身占屏比例）：0.19 → 0.25 同理。
- `post` 里还有爆炸闪光/慢镜头暗角，属于动态效果，非持续清晰度因素。

## 4. 更深层的方案（若参数调整不够）

如果降 pixelSize 后性能不可接受，但又要更清晰，需改渲染架构（成本递增）：

1. **分离 UI 与场景分辨率**：场景保持 px=2~3，但把 HUD/文字单独用高分辨率 DOM/Canvas 画（当前 HUD 已在屏幕空间，但状态栏等可能与场景同缓冲）。
2. **选择性超采样**：只对机体区域用 px=1 渲染后合成（需要 scene.ts 支持局部高分辨率视口，改动大）。
3. **替代放大算法**：当前 `image-rendering:pixelated`（最近邻）。可试 `crisp-edges` 或自定义 shader 做轻度锐化/反锯齿，但会破坏像素艺术风格，需权衡。
4. **GPU 化**：把 `scene.ts` 的软件光栅化搬到 WebGL fragment shader（体素数据传纹理），可同时拿到清晰度与帧率 —— 等价于做一次 GLSL 移植，是 004 文档方案 E 的一部分。
5. **复用天然高分辨率层**：火焰层已是全分辨率 WebGL（`fighter-jet-eject.tsx:233`），可借鉴其思路把更多特效移到独立高分 canvas。
