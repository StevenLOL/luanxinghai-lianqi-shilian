## 1. 如何运行

双击 `scripts/mvp_air_to_ground.html` 即可，无需服务器、无需联网。

- **v2 起依赖 `scripts/assets/` 下的 4 张角色素材**（相对路径），请保持 `mvp_air_to_ground.html` 与 `assets/` 的目录关系；
- 素材加载失败时自动回退到程序化切片体绘制，只拷 HTML 单独打开也不会白屏；
- 无 ES module / importmap / fetch，`file://` 下可运行（避开 `docs/005` 的 CORS 坑）；
- 浏览器建议 Chrome / Edge。

### 素材处理

AI 生成的 PNG 是 RGB 白底（水墨晕染），直接贴会有白方块。`scripts/08_strip_png_bg.js` 用 Node 内置 zlib 实现纯 JS 抠图：从四边 flood-fill，只删「连通边缘的浅色低饱和像素」，角色内部被描边包围的浅色衣袍得以保留。生成物为 `*_cut.png`（RGBA），游戏加载的是 cut 版。

用法：`node scripts/08_strip_png_bg.js scripts/assets`

## 4. 已复现并修复的 bug

**玩家飞剑渲染成巨大青色圆球，挡住画面中心。**

- 根因：玩家离相机近，投影缩放 `s = focal/z` 很大；御剑者半径写成 `(3-i*0.5)*s`、剑身半宽 `2.4*s`，导致世界尺寸被放大成数十像素的色块。
- 修复：御剑者半径改为 `0.75*s` 量级、剑身半宽 `0.7*s`，颜色加深与天空区分。
- 举一反三：所有**跟随相机的近景对象**，绘制尺寸必须按世界单位 × 投影缩放保守取值；不能套用远景对象的系数。写完后必须实际截图看一眼，不能只靠代码审阅。

## 5. 验证记录

- **JS 语法**：`node --check` 通过；
- **运行时逻辑**：Node + mock canvas 跑 6 组场景（飞行/剑诀/雷池/俯冲/切视角/重开），零运行时错误；
- **实际渲染**：无头 Chrome 截图多轮。v1 第一次发现巨球 bug 并修复；v2 实机截图确认海洋（深/浅蓝+波纹）、沙滩→草地→雪顶分层、云层、剑仙水墨素材、妖兽素材与血条、HUD 全部正常。

**v2 新增验证**：山海地形断言（陆地/海洋均存在、原点为陆地、10 个敌人 0 个在海上）、26 组云、Boss 触发（击杀 5 → 麒麟 360HP）、4 张素材路径正确。

**截图工具坑**：`--virtual-time-budget` + rAF 游戏循环会导致截图挂死或空白帧；改用**无虚拟时间的实时截图**（加载后等文件落盘）才拿到正确画面。这与 docs/006 记录的"纯色帧不是错误而是状态问题"是同类陷阱。
