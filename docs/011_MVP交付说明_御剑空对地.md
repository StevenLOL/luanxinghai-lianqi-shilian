## 1. 如何运行

双击 `scripts/mvp_air_to_ground.html` 即可，无需服务器、无需联网。

**手机 / 局域网访问（v2.13 新增）**：在项目根目录执行 `python scripts/10_serve_mvp.py 8000`，
启动后终端会打印局域网地址（本次为 `http://192.168.1.5:8000/scripts/mvp_air_to_ground.html`）；
手机连同一 WiFi 打开即可。服务绑定 `0.0.0.0`，带 no-cache 头，便于改完立刻刷新。

- **v2 起依赖 `scripts/assets/` 下的角色素材**（相对路径；v2.5 起为 5 张，含背视角），请保持 `mvp_air_to_ground.html` 与 `assets/` 的目录关系；
- 素材加载失败时自动回退到程序化切片体绘制，只拷 HTML 单独打开也不会白屏；
- 无 ES module / importmap / fetch，`file://` 下可运行（避开 `docs/005` 的 CORS 坑）；
- 浏览器建议 Chrome / Edge。

### v2.1 新增内容（2026-11-18，弹道物理 + 气血自愈）

> 用户原话：`投射物应该 遵守一点 物理规律，比如 投射物 会受重力 而 加速/减速， 地面对空 的投射物 回落回地面，等等。主角的 hp 也可慢慢恢复。`

| 项 | 实现 |
|---|---|
| 重力常量 | `GRAVITY = 24`（世界单位/秒²），所有投射物每帧 `v.y -= GRAVITY*dt` |
| 弹道解算 | `ballistic(from,to,horizSpeed)`：由起点/目标/水平速度反解含竖直分量的初速度，使抛物线命中目标高度 |
| 玩家剑诀 | 不再直线穿模；按抛物线飞行，触地爆炸并对落点周围敌人造成 26 伤害 |
| 敌修弹丸 | 地面对空也走抛物线；未命中玩家则回落地面，溅起尘土后消失，而不是一直飞到寿命耗尽 |
| HP 自愈 | 玩家 `lastHit` 记录受击时刻；脱战 3 秒后以 2.2 HP/秒恢复；再次受击立即重置计时 |
| HUD 提示 | 未满血时显示两态：受击后 3 秒内「气血回复：受击中…」，之后「气血回复中 +2.2/秒」 |

### v2.12 新增内容（2026-11-19，雷达坐标核实与修正）

> 用户原文：`雷达图，你核实下，好像不准。` 核实结论：**确实有 bug**。

| 项 | 说明 |
|---|---|
| 根因 | 雷达用 `fwd=dx·cos(hd)+dz·sin(hd)`、`rgt=-dx·sin(hd)+dz·cos(hd)`；但项目朝向约定是 `facingVec(hd)=(sin hd,-cos hd)`（hd=0 朝 -z）。雷达的"前向"实际是右向、"右向"实际是负前向——正前方敌人被画到雷达左侧、正右方被画到上方，与 HUD 文字方位（`nearestEnemyInfo()`，其计算正确）互相矛盾 |
| 修正 | 雷达基向量统一到 `facingVec` 约定：`fwd=dx·sin(hd)-dz·cos(hd)`、`rgt=dx·cos(hd)+dz·sin(hd)`，与 `nearestEnemyInfo()` 完全一致的分解；正上=正前、正右=正右 |
| 保留 | 前向扇形、同心圈、距离贴边、Boss 金色高亮与描边均不变 |

举一反三：这是**同一概念（朝向基向量）在两处实现不一致**导致的 bug——一处（`nearestEnemyInfo`）对、一处（`drawRadar`）错，因此文字与图形会互相矛盾。后续涉及"相对方位"的新功能，应统一调用 `facingVec()` 或其分解，不再各自手写 sin/cos，避免第三处再次漂移。

### 素材处理

## 4. 已复现并修复的 bug

**玩家飞剑渲染成巨大青色圆球，挡住画面中心。**

- 根因：玩家离相机近，投影缩放 `s = focal/z` 很大；御剑者半径写成 `(3-i*0.5)*s`、剑身半宽 `2.4*s`，导致世界尺寸被放大成数十像素的色块。
- 修复：御剑者半径改为 `0.75*s` 量级、剑身半宽 `0.7*s`，颜色加深与天空区分。
- 举一反三：所有**跟随相机的近景对象**，绘制尺寸必须按世界单位 × 投影缩放保守取值；不能套用远景对象的系数。写完后必须实际截图看一眼，不能只靠代码审阅。

**v2.1 弹道改造中的三个测试/实现 bug。**

- `ballistic()` 最初返回 `{vx,vy,vz}`，但更新循环按 `{x,y,z}` 读取，导致 `vy0=undefined`、下一帧 `NaN`，剑诀不落地。已统一为 `{x,y,z}`。
- 测试 harness 的 `step()` 每轮从 `i*16.7` 取时钟，后续 `dt` 变负，重力方向测反。已改成单调累加时钟。
- T4 曾用数组下标 0 追踪敌修弹丸，被敌修新生成的弹丸覆盖；同时控制台引用了不存在的 `ebUp/ebDown`。已改成保留 `probeBullet` 对象引用，并按抛物线顶点前后取样。
- 举一反三：**物理测试必须同时锁定对象引用、单调时钟和隔离输入**；断言"先升后落"不能在顶点之前取样，否则会把上升段误判成失败。

**v2.2 测试替身契约 bug。**

- harness 里塞入的 dummy 目标最初只有 `pos/hp/dummy`，但 `update()` 会把未知类型当敌修处理并调用 `tryAutoAttack('enemy', dummy)`，因缺少 `cds/qi/facing` 抛错，导致后续断言未执行。
- 已给 dummy 补全敌方实体字段；举一反三：**测试替身必须满足被测试系统的完整契约，而不只是当前断言路径**。

**v2.4 初版云形与材质花斑。**

- 初版云用多层椭圆堆叠，视觉像「白色千层圆盘」；草地 / 沙地 / 雪地用 hash 随机选材质，出现棋盘花斑。
- 修复：云压扁为底 / 侧 / 顶三层扁平椭圆，云簇移到玩家周围 120~440 单位环带；地形材质改按高度与坡度分层，浪花概率降低；网格从 `step=30, range=13` 细化为 `step=25, range=16`。
- 举一反三：视觉移植不只是搬参数和调色板，还必须验证在**当前投影**下的尺度、遮挡和密度；必须截图迭代，不能只看代码。

**v2.5 A/D/S 相机抖动。**

- 根因是一个闭环：移动方向由 `cam.yaw` 算 `fwd/right`，随后又把移动方向写回 `cam.yaw`。A/D 横移时角色一直沿“当前相机的右方”走，相机又去追这个方向，形成画圈；S 时目标角是 180°，原始 `lerp` 在 +π/-π 边界走长弧，表现为突然甩镜头。
- 修复：新增独立 `player.heading`；A/D 改转向、W/S 沿 heading 平移；相机用 `lerpAngle()` 只跟随 heading；视野锥与自动攻击也改读 heading。
- 举一反三：**相机跟随对象时，跟随目标和输入基向量必须来自不同状态**。若“输入方向”和“相机朝向”互相写入，任何转向/后退都会变成反馈震荡；角度插值必须走最短弧。

**v2.5 背视角飞剑朝向反复出错。**

- 初版脚下飞剑斜跨画面；局部编辑版仍斜向；重新生成版虽然竖直但剑尖朝镜头；共 4 版才正确。
- 修复：最终采用 `raw4`，脚下飞剑剑尖朝画面上方/场景深处、剑柄在脚下；水印由 `scripts/09_prepare_sword_back.js` 清除后抠图。
- 举一反三：AI 生图对“朝向/透视”这类空间语义不稳定，必须**逐张目视验收**并在需求里写清屏幕空间方向（朝上/朝下、是否斜跨），不能只写“与朝向一致”。

## 6. v2.13 性能优化与手机端适配（2026-11-19）

> 用户原文：`感觉有点 卡了，你分析下， 1 提升性能  2 反思 手机端打开游戏的 效果，你起个服务 我看看`

### 6.1 量化剖析（优化前基线）

CDP 逐阶段计时，1424×805、DPR 1、无头 Chrome，采样 6 秒：

| 阶段 | 每帧均耗 | 占比 | 热点来源 |
|---|---:|---:|---|
| render 合计 | 5.06ms | 100% | — |
| drawTerrain | 3.74ms | 74% | 32×32=1024 格，每格 4 角 + 1 中心 `terrainH`，`terrainColor` 两次 `continent`，约 1.4 万次噪声采样/帧 |
| drawClouds | 0.66ms | 13% | 48 簇 puff，每 puff 三层椭圆 + 离屏 `destination-out` 抠洞 |
| drawProjectiles | 0.43ms | 8% | 弹体拖尾 + 粒子 + 飘字 |
| drawHUD | 0.25ms | 5% | 约 20 次 `fillText` + 3 个渐变对象/帧 |

结论：地形是主要瓶颈，云层次之；HUD/粒子/敌人排序不是瓶颈。

### 6.2 优化措施

1. **角点共享**：预计算 `(2r+1)²` 个格点高度到 `Float32Array`，相邻格复用；`terrainH` 调用由 4096 降到 1089 次/帧。
2. **坡度缓存**：`continentFast()` 缓存网格中心两侧采样，上限 6000 条防增长。
3. **分配削减**：`cells` / 敌人排序 / 云簇排序数组全部复用；眼点积内联，去掉每格 3 个临时对象。
4. **云降采样**：离屏云画布按 `min(DPR, 0.7)` 渲染再放大；手机端 `cloudRank` 9→6。
5. **质量档**：`QUALITY` 集中管理 step/range/cloudRank/edgeStroke/trees/seaSparkle；
   主循环每 90 帧评估平均帧时，>24ms 降一档、<14ms 升一档，带 3~5 秒冷却防抖。
6. **DPR 封顶 1.5**：`canvas.width=W*dpr`，绘制坐标仍用 CSS 像素；3x 全量是 9 倍像素，不划算。

### 6.3 反直觉发现 + 严重回归（重要）

**A. V8 deopt 陷阱**：曾加"整格屏幕包围盒剔除"（每帧少画约 840 格），期望大幅提速；实测 `drawTerrain`
反而从 1.58ms 恶化到 11.64ms。用 git 原版函数做 CDP 运行时 A/B 对照后定位到该 `continue`
分支导致 V8 反复 deopt。已移除并在代码内留注释。
**教训：少画格子不等于更快，所有"显然有效"的优化必须实测。**

**B. off-by-factor 导致地图只剩一半（用户当场发现）**：首版角点共享重构时，把格子循环写成
`i<range`，但原版 `range=16` 是**半宽**，格数应为 `(2*range)²=1024`。结果只画 `16×16=256` 格，
且起点 `ox=(cx-range)*step` 使这 256 格落在玩家左后方——截图表现为地图只有左半边、右侧全是天空，
用户反馈「地图怎么变 一半了？」后才定位。修正为 `i<range*2`，截图 `others/mvp_v213_fixed_desktop.png`
复核与 v2.12 一致。
**教训：① 重构循环时先写清“总量 vs 半宽”的语义并加注释；② 性能优化必须同时做视觉回归，
只看耗时数字会把“少画 3/4 画面”误当成提速；③ 此前报告的 -58%/-38% 全部作废。**

## 7. v2.14 剑舞·万象翻滚（2026-11-19）

> 用户原文要点：初始高度 25 丈；J 键/手机独立按钮触发机动翻滚，CD 5s；手机去掉 1234/自动/俯冲，只留升降与翻滚；参考战机横滚/桶滚/半筋斗翻转/大迎角附加滚转设计修仙化动作。

### 7.1 动作设计与四段机动的映射

| 战机机动 | 修仙化表达 | 游戏内效果 |
|---|---|---|
| 大迎角附加滚转 | 起手剑尖上扬、`fxRing`+`burst` 蓄势 | 视觉起势，剑气聚拢 |
| 横滚 360° | 角色绕屏幕中心旋转（全程 720° 缓入缓出）+ 青金双环护体 | **全程短无敌**（每帧续 0.08s `inv`），规避弹幕 |
| 桶滚 | 沿朝向冲 72 丈 + 侧摆 9 丈的螺旋突进 | 快速转移；剑气横扫路径敌人各一次 30 伤害 |
| 半筋斗翻转（殷麦曼） | 抬升 13 丈后回落 | 抢高度：翻滚结束设定高度 +4（受 ALT_MAX 约束） |

左右翻滚方向每次交替，连续使用观感更像「剑舞」而非机械重复；不耗灵力（与俯冲区分），靠身法而非法术。

### 7.2 实现与控件

- `startRoll()` 负责 CD/状态置位与起手特效；`updateRoll(dt)` 返回 true 时接管本帧移动与高度（与普通飞行、俯冲互斥），灵力回复/自动斗法/敌人行动照常。
- 电脑 **J** 键触发（原 J 是飞剑备用键，飞剑仍可用 1 / 左键；K 保留火球备用）；HUD 显示「剑舞翻滚 CD x.xs / 就绪」。
- 手机按钮从 9 个精简为 **升 / 降 / 剑舞翻滚** 三个，翻滚按钮 CD 中变暗；手机 HUD 同步隐藏已无控件对应的技能行、自动/视野行与相机档位行，鼠标准星也不再绘制。
- 初始高度 `DEFAULT_ALT=25`，player 初始 `pos.y=DEFAULT_ALT+2`，避免开局实际高度仍是旧值。

### 7.3 踩坑与验证

- **主循环停摆 bug**：`const groundP` 最初留在 `if(!rolling)` 块内，翻滚接管分支在块外引用它导致 `ReferenceError`，CD 不减、位移为 0。用 CDP `Runtime.exceptionThrown` 抓到后提到块外解决。教训：给大函数加「新分支接管」时，检查原分支内 `const` 的作用域是否被块外引用；语法检查发现不了这类错误。
- `scripts/14_test_roll.js` CDP 实测 **11/11 通过**：初始高度、J 触发、CD 5s、翻滚无敌、桶滚位移、CD 期间不重置、状态释放、高度收益 +4、手机三按钮、隐藏提示条、手机翻滚按钮。
- 截图：`others/mvp_v214_roll_desktop.png`、`others/mvp_v214_roll_mobile.png`；性能无回归（桌面 render 4.64ms、手机 2.68ms）。

## 8. v2.15 被击败来源可追溯 + 击杀回放（2026-11-19）

## 9. v2.16 气血随时回 + 剑舞连段 + Kill Cam 子弹时间（2026-11-19）

> 用户原文：`1 自动回放 速度 太快了，有没有 那种 慢加速 的 特效呢？；气血恢复，应该随时生效，你看看恢复值 是真正的恢复值吗？感觉不对；剑舞机动消耗 20法力冷却 0.5 s，只要法力够，应该可以连续机动。`

### 9.1 气血恢复：显示值 = 真实速率

用户说"感觉不对"的根因有两层：① `game.time-player.lastHit>3` 是三秒硬门槛，受击后完全不回血；
② 基础速率仅 2.2/秒 ≈ 血条 3.7px/秒，肉眼根本看不出在动。

| 项 | 改动前 | 改动后 |
|---|---|---|
| 触发门槛 | 受击后 3 秒 | 受击后 0.6 秒（= 无敌帧时长） |
| 基础速率 | 2.2/秒 | **5.0/秒**（+0.45/层） |
| HUD | 受击时显示「受击中…」，满血时**不显示** | 三态：停顿剩余秒数 / 真实速率 / 满血也显示速率 |

判定统一走 `hpRegenDelay()`（距上次受击秒数）与 `hpRegenActive()`，
HUD 与 `update()` 引用同一份数据 ⇒ 显示值与 `dt*pRegenHp()` 严格一致。

### 9.2 剑舞·万象：20 灵力 / 0.5 秒 / 可连段

原版 5 秒冷却 + 0 消耗 ⇒ 一次翻滚后要干等，且与灵力系统完全脱钩。
改成短冷却 + 耗蓝后，翻滚从"一次性大招"变成"可连续展开的机动"：

| 机制 | 做法 |
|---|---|
| 连段模型 | `chainT`（累计翻滚时间，角度/速度/相位全连续）、`pressT`（最近按键）、`seg`（段数）、`segT`（本段计时） |
| 续段 | 翻滚中 CD 转好再按 J ⇒ `seg+1`、轨迹不重置 ⇒ **位置与旋转完全连续**，不会"每段重新起步" |
| 按住连滚 | `keys['j']` / `touch.rollHeld` 在 CD 转好时自动续接 ⇒ **按住 J 或手机按住翻滚键即可持续机动**，直到灵力耗尽 |
| 连段窗口 | `ROLL_CHAIN_WINDOW = 1.05s`（= 一段时长）：按一次恰好滚完整一段，段内再按即可续 |
| 高度收益 | 由"结束时一次 +4"改为**按翻滚时长连续累计**（滚满一段 ≈ +4.01 丈），连段不突兀 |
| 剑气横扫 | `hit` 集合每段重置 ⇒ 连段可对同一敌人反复扫到 |
| 门槛 | 灵力不足时无法发动，HUD 明示「灵力不足（需 20）」而非"按了没反应" |

### 9.3 Kill Cam：子弹时间式慢加速

原回放 0.9~1.6 秒掠完全程，看不清"从激发到命中"的因果链。

- **时间缩放曲线** `killCamTimeScale(t)`：0.18 倍速起步 → 1.35 秒内 smoothstep 加速到 1.0 倍速；
  弹道内部时间 `shotT` 只按 timeScale 推进 ⇒ 真实耗时被拉长约 **1.6 倍**。
- **慢动作视觉** `drawKillCamFx()`：径向速度线（10~36 条随速度增减）+ 青蓝色调 + 径向暗角，
  强度均与 `1-ts` 反相关，加速后自动消退；法术外圈加青蓝能量描边环。
- **可读性** `drawKillCamOverlay()`：左上角倍速读数「时缓 ×0.41」+ 右下角时间刻度尺（含滑块）。
- 相机在慢动作期做缓慢横移呼吸，倍速越高越回归原位。

### 9.4 顺手修掉的真缺陷（举一反三）

- `reset()` 漏了 `cds.roll` 与 `roll` 字段 → 重开后翻滚状态异常，已补齐。
- 手机端点画布会合成 `mousedown` 误放飞剑术（违背 v2.14「手机只保留升降+翻滚」）→ `IS_TOUCH` 时拦截鼠标施法。

  `13_test_touch.js` **8/8**（三键布局、按住翻滚连段、点画面不误放技能）；`15_test_killcam.js` **13/13** 零回归。
- 性能：桌面 62.9fps / P95 21.1ms；Kill Cam 回放期同为 62.9fps（视觉层无开销回退）。
- 截图：`others/mvp_v216_rollchain_desktop.png`、`mvp_v216_killcam_slow_desktop.png`、
  `mvp_v216_killcam_fast_desktop.png`、`mvp_v216_rollchain_mobile.png`。
- 踩坑：① 回血速率实测一度显示 0.89/秒 —— 根因是测量窗口内敌人重生并攻击污染净增量，
  改用「持续清空敌人 + 逐帧 hook」复测得 4.98/秒，确认代码正确、**测试需隔离**；
