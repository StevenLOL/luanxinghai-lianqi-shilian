### v2.1 新增内容（2026-11-18，弹道物理 + 气血自愈）

> 用户原话：`投射物应该 遵守一点 物理规律，比如 投射物 会受重力 而 加速/减速， 地面对空 的投射物 回落回地面，等等。主角的 hp 也可慢慢恢复。`

| 项 | 实现 |
|---|---|
| 重力常量 | `GRAVITY = 24`（世界单位/秒²），所有投射物每帧 `v.y -= GRAVITY*dt` |
| 弹道解算 | `ballistic(from,to,horizSpeed)`：由起点/目标/水平速度反解含竖直分量的初速度，使抛物线命中目标高度 |
| 玩家剑诀 | 不再直线穿模；按抛物线飞行，触地爆炸并对落点周围敌人造成 26 伤害 |
| 敌修弹丸 | 地面对空也走抛物线；未命中玩家则回落地面，溅起尘土后消失，而不是一直飞到寿命耗尽 |
| HP 自愈 | 玩家 `lastHit` 记录受击时刻；脱战 3 秒后以 2.2 HP/秒恢复；再次受击立即重置计时 |
| HUD 提示 | 未满血时显示两态：受击后 3 秒内「气血回复：受击中…」，之后「气血回复中 +2.2/秒」 |

### 素材处理

AI 生成的 PNG 是 RGB 白底（水墨晕染），直接贴会有白方块。`scripts/08_strip_png_bg.js` 用 Node 内置 zlib 实现纯 JS 抠图：从四边 flood-fill，只删「连通边缘的浅色低饱和像素」，角色内部被描边包围的浅色衣袍得以保留。生成物为 `*_cut.png`（RGBA），游戏加载的是 cut 版。

背视角素材是绿底并带工具水印，另用 `scripts/09_prepare_sword_back.js`：先清掉右下水印区域，再做绿幕抠图与边缘溢色抑制，输出 `sword_immortal_back_cut.png`。注意脚下飞剑曾连续三版朝向错误（斜跨画面、剑尖朝镜头），最终版才做到剑尖朝场景深处；不要拿早期 `raw/` 或 `master_back/` 直接替换。

用法：`node scripts/08_strip_png_bg.js scripts/assets`；单张背视图：`node scripts/09_prepare_sword_back.js <raw.png> <cut.png> <cleanGreen.png>`。

## 4. 已复现并修复的 bug

**玩家飞剑渲染成巨大青色圆球，挡住画面中心。**

- 根因：玩家离相机近，投影缩放 `s = focal/z` 很大；御剑者半径写成 `(3-i*0.5)*s`、剑身半宽 `2.4*s`，导致世界尺寸被放大成数十像素的色块。
- 修复：御剑者半径改为 `0.75*s` 量级、剑身半宽 `0.7*s`，颜色加深与天空区分。
- 举一反三：所有**跟随相机的近景对象**，绘制尺寸必须按世界单位 × 投影缩放保守取值；不能套用远景对象的系数。写完后必须实际截图看一眼，不能只靠代码审阅。

**v2.1 弹道改造中的三个测试/实现 bug。**

- `ballistic()` 最初返回 `{vx,vy,vz}`，但更新循环按 `{x,y,z}` 读取，导致 `vy0=undefined`、下一帧 `NaN`，剑诀不落地。已统一为 `{x,y,z}`。
- 测试 harness 的 `step()` 每轮从 `i*16.7` 取时钟，后续 `dt` 变负，重力方向测反。已改成单调累加时钟。
- T4 曾用数组下标 0 追踪敌修弹丸，被敌修新生成的弹丸覆盖；同时控制台引用了不存在的 `ebUp/ebDown`。已改成保留 `probeBullet` 对象引用，并按抛物线顶点前后取样。
- 举一反三：**物理测试必须同时锁定对象引用、单调时钟和隔离输入**；断言"先升后落"不能在顶点之前取样，否则会把上升段误判成失败。

**v2.2 测试替身契约 bug。**

- harness 里塞入的 dummy 目标最初只有 `pos/hp/dummy`，但 `update()` 会把未知类型当敌修处理并调用 `tryAutoAttack('enemy', dummy)`，因缺少 `cds/qi/facing` 抛错，导致后续断言未执行。
- 已给 dummy 补全敌方实体字段；举一反三：**测试替身必须满足被测试系统的完整契约，而不只是当前断言路径**。

**v2.4 初版云形与材质花斑。**

- 初版云用多层椭圆堆叠，视觉像「白色千层圆盘」；草地 / 沙地 / 雪地用 hash 随机选材质，出现棋盘花斑。
- 修复：云压扁为底 / 侧 / 顶三层扁平椭圆，云簇移到玩家周围 120~440 单位环带；地形材质改按高度与坡度分层，浪花概率降低；网格从 `step=30, range=13` 细化为 `step=25, range=16`。
- 举一反三：视觉移植不只是搬参数和调色板，还必须验证在**当前投影**下的尺度、遮挡和密度；必须截图迭代，不能只看代码。

**v2.5 A/D/S 相机抖动。**

- 根因是一个闭环：移动方向由 `cam.yaw` 算 `fwd/right`，随后又把移动方向写回 `cam.yaw`。A/D 横移时角色一直沿“当前相机的右方”走，相机又去追这个方向，形成画圈；S 时目标角是 180°，原始 `lerp` 在 +π/-π 边界走长弧，表现为突然甩镜头。
- 修复：新增独立 `player.heading`；A/D 改转向、W/S 沿 heading 平移；相机用 `lerpAngle()` 只跟随 heading；视野锥与自动攻击也改读 heading。
- 举一反三：**相机跟随对象时，跟随目标和输入基向量必须来自不同状态**。若“输入方向”和“相机朝向”互相写入，任何转向/后退都会变成反馈震荡；角度插值必须走最短弧。

**v2.5 背视角飞剑朝向反复出错。**

- 初版脚下飞剑斜跨画面；局部编辑版仍斜向；重新生成版虽然竖直但剑尖朝镜头；共 4 版才正确。
- 修复：最终采用 `raw4`，脚下飞剑剑尖朝画面上方/场景深处、剑柄在脚下；水印由 `scripts/09_prepare_sword_back.js` 清除后抠图。
- 举一反三：AI 生图对“朝向/透视”这类空间语义不稳定，必须**逐张目视验收**并在需求里写清屏幕空间方向（朝上/朝下、是否斜跨），不能只写“与朝向一致”。
